# 变更记录

## 1.0.0 — 未发布

首个独立仓库发布：通用的“网址取数 → 串口回传”插件。设备输出命中规则后，从 HTTPS 接口取回数据（或使用固定值、映射表），再回传到串口。

### 功能

- 配置由 Schema 驱动：顶层字段描述回传内容来源，`rules` 数组逐条描述设备动作，表单中按字段联动显隐。
- 回传内容来源 `replySource`：
  - `http`：宿主持有的登录会话 + 同源取数接口，可配置 GET / POST、请求体模板（`$value`）、响应字段路径、纯文本响应、登录失效状态码与业务 code；
  - `static`：固定回传内容，不依赖 `auth.session`；
  - `map`：按设备输出查本地映射表，未命中直接失败，不写入任意内容。
- 规则参数均可配置：触发词（逗号分隔、区分大小写、整行匹配、折叠退格、容忍提示符）、内容匹配（`prefix` / `base64-line` / `line`）、结果判定（`line` / `prompt-repeat` / `none` 及提示文本与时序）、回传模板（`$value`）、行尾（`cr` / `lf` / `crlf` / `none`）、等待设备输出 / 内容有效期 / 等待结果超时、扣键缓存上限。
- 动作 `run`（可用 `args.ruleId` 指定规则）与 `reset`（取消等待、重置监听缓存并丢弃扣住的输入）。
- 只有手动规则时不再拒绝启动：记录警告并保留手动动作；`auto: false` 时即使宿主开启自动监听也不会扣键或自动回传。
- 回传内容字符集（`base64` / `printable`）与长度范围校验，三种来源共用。
- 首次使用缺少 `loginUrl` / `authCheckUrl` / `fetchUrl` 时给出逐项提示，而不是只报“地址无效”。
- 使用宿主通用能力 `stream.subscribe`、`stream.acquire`、`stream.hold` / `releaseHold` 与 `auth.session`，不依赖 DevKit 内部类。API v2 清单声明 `transports: ["serial"]` 和 `stream.exclusive` / `auth.session`。

### 安全与隐私

- 回传内容只以 `secret` 写入，不回显到终端历史。
- Cookie 由宿主 Chromium 独立持久分区保存，不进入插件配置、宏或诊断。
- 取数失败只输出字段结构与业务 code，不输出响应中的内容值。
- 登录窗口限制主框架跳转来源并拒绝弹窗。

### 验证

- 覆盖三种内容来源（含 GET 取数与纯文本响应）、手动回传、自动触发与扣键补发、两类拒绝判定、登录过期重登、配置校验、回传模板与 `result: none`、跨批次分行匹配及内容不进入日志/状态。
- 停止实例时立即取消正在等待的设备输出或结果，释放事务；迟到取得的租约不得继续写入。
- 增加官方 SDK 契约检查，验证目录 / JSON 两种真实安装路径、secret 标记以及 HTTP 取数流程。
